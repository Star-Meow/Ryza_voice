# 目標結構框架（各文件應該有什麼）

本文件決定每份文件**應該有什麼、不應該有什麼**，後續的修改以此為準；`inventory.csv` 的去向也會依此更新。
只存在於 `docs/repo-boundary` branch，合併前移除。

## 共用原則

1. **不用 issue 的框架**：「Part 1／Part 2」、「已完成／進行中」、「驗收要件」、「對應 issue 要求」只留在 issue 與 PR。
   repo 內一律用**模塊**命名。
2. **一個主題只有一個來源**：其他地方只放一行摘要加連結，不複製內容。
3. **文件類型決定內容**：

| 類型 | 位置 | 放什麼 | 不放什麼 |
|---|---|---|---|
| 入口 | `README.md` | 是什麼、怎麼裝、怎麼跑、去哪看 | 方法細節、數據、決策理由、進度 |
| 設計 | `docs/` | 為什麼這樣做：約束、選項、比較、結論 | 執行步驟、結果數據 |
| 流程 | `docs/` | 怎麼做：輸入、步驟、指令、產出、注意事項 | 當次執行紀錄、驗收口吻 |
| 參考 | `docs/` | 查詢用：工具目錄、坑記錄 | 過程敘事 |
| 結果 | `reports/` | 做了之後得到什麼：設定、數據、分析、限制 | 重現步驟、停止點、等待放行、branch 狀態 |
| 目錄說明 | `samples/README.md` | 這個目錄裡有什麼、怎麼產生 | 評估結論 |

4. **一律刪除的字樣**：「計畫 §x」（計畫不在 repo）、「本 session」、「等待放行」、「停止點」、「尚未 commit」、「PM 裁示」（改為中性敘述「決定…，理由…」）。

## 模塊

所有文件共用這組模塊名稱：

| 模塊 | 做什麼 | 流程文件 | 結果文件 |
|---|---|---|---|
| 語音解包 | KTSR 音聲庫 → WAV、索引 | docs/03 | — |
| 說話者篩選 | 在無名稱的主庫中找出ライザ | docs/04 | — |
| 轉譯資料集 | ASR → 過濾 → 去重 → 校正 → 訓練清單 | docs/05 | asr_report、correction_diff |
| 資料切分 | train／test／eval10 | docs/06 | split_report |
| TTS 微調與推論 | GPT-SoVITS v4 LoRA 環境、預處理、訓練、推論 | docs/07（設計見 docs/02） | finetune_report、logs/ |
| 評估 | 聲線相似度、可懂度 CER、主觀試聽 | docs/07 評估節 | finetune_report、defect_triage |
